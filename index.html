Agent-Tickets

A peer-to-peer event-ticket marketplace where humans and AI agents alike can list and browse tickets, designed to settle in USDC escrow on Solana.

Open exchange demo →

Problem

Resale platforms charge 20–30% in combined fees, and none of them let an AI shopping agent transact — every checkout assumes a human clicking a webpage. Meanwhile the P2P resale that already happens in DMs and group chats has zero protection for either side.

Solution

One live marketplace with two front doors: a human lists a ticket with a simple form, an AI agent lists or reads inventory with a single JSON API call, and both see the same listings instantly. Agents are first-class users of the exact same inventory — not scrapers. The Solana USDC escrow settlement layer is fully designed (spec committed in the repo) and slots onto this listing rail next.

Core features (V1)

  • List a ticket for sale via web form: event name, date, venue, price in USDC
  • Live listings page — new tickets appear instantly for everyone
  • Agent JSON API: POST /api/listings to list a ticket, GET /api/listings to read inventory — same live data as the web UI
  • Validation with machine-readable errors so agent callers can self-correct

Out of scope (for now)

  • On-chain escrow purchase/release flow — fully designed in the repo's design doc, not live yet
  • MCP server wrapper (the JSON API is the agent surface for now)
  • Fiat onramp, disputes/arbitration, KYC/compliance, mobile apps
  • Native NFT ticket issuance and venue/door verification

Success criteria

A judge lists a ticket through the web form and watches it appear instantly in live listings; then an AI agent creates a second listing through POST /api/listings and both listings show in GET /api/listings and on the page — all live, in under 30 seconds.

Tech stack

Zero-dependency Node.js server (web UI + JSON API), Solana/Anchor USDC escrow spec'd in-repo, built with Claude Code + Cursor.

Team tracks — pick yours

Track A — "The Vault"

Solana person

Build the on-chain safe that holds the buyer's money until the deal is done. Nobody gets paid until delivery is confirmed or a timer runs out.

Track B — "The Brain"

Backend

The backend server that manages everything — the database, the safety rails (no double-buys), and the one place all data flows through. Think of it as the bank that manages the vault.

Track C — "The Robot Door"

Agent API

The entrance AI agents use. Same inventory, same rules, but an AI can search/buy/confirm without a human touching a browser. This is the differentiator — no other ticket marketplace has this.

Track D — "The Human Door"

Web + biz

The website for normal people, plus the business stuff (applying for Stripe/Crossmint today, reaching out to conference organizers for supply).

Three rules

  1. Freeze the shared contracts together on day 1.
  2. The critical path flows A→B→C (D runs in parallel — help the track to your left if you finish early).
  3. The website can never do something the agent API can't — that's the whole product promise.
