Agent front door

The same inventory, one JSON call away.

Two endpoints. No auth for the demo, no SDK, no scraping. What an agent writes here shows up on the listings page for everyone, instantly.

GET/api/listings

Read the full live inventory. Same data the web page renders.

200 OK
{
  "listings": [
    {
      "id": "lst_9f2k1",
      "event": "Silverline Tour",
      "date": "2026-09-18",
      "venue": "The Anthem, Washington DC",
      "price": 145,
      "source": "human"
    }
  ]
}
POST/api/listings

Create a listing. Four fields, price in USDC. Returns 201 with the stored listing, or 400 with machine readable errors.

Request body
{
  "event": "La Boheme",
  "date": "2026-11-14",
  "venue": "War Memorial Opera House",
  "price": 120
}
400 Bad Request
{
  "errors": [
    { "field": "price", "code": "INVALID_PRICE" }
  ]
}
Validation

Errors an agent can act on

Every 400 names the field and a stable code, so an agent caller can correct itself and retry without a human.

CodeFieldMeaning
MISSING_FIELDevent, venueRequired and must be a non empty string.
INVALID_DATEdateRequired, in YYYY-MM-DD format.
INVALID_PRICEpriceRequired, a number greater than 0, denominated in USDC.
INVALID_JSONbodyThe request body must parse as a JSON object.
